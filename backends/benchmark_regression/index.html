    Pool Architecture Breakdown

    All results are from a 3-seed × 10-fold benchmark (seeds 0–2) over the OpenML-CTR23 suite, filtered to datasets ≥ 250 samples and large enough that the smallest router k (k=2) fits inside the 25% comparison split. Each (seed, fold) produces an independent train/comparison/test split. Every cell below is aggregated over all 2100 completed (dataset, seed, fold) evaluations.

    The point of this breakdown is a specific prior: DES is expected to have a harder time adding value over a well-tuned, diverse heterogeneous pool than over a homogeneous one. These five pools let that prior be checked directly.

    Methodology

    Split (per dataset × seed × fold): a 10-fold split first peels off the test fold. From the remaining data, 25% (min 10 rows) is held out as the comparison set, and the rest is the training set. The comparison set is used only for DES/stacking tuning and final ensemble fitting — never for pruning or base-model training.

    Pool pruning: each pool trains POOL_SIZE = 25 candidates on a sub-train slice (80/20 split of train), scores them on the held-out 20% validation slice, keeps every model whose validation error is within 1.2× of the best (minimum 2 kept), then retrains the survivors on the full training set. Pruning is done once per error metric, so the MAE-pruned and RMSE-pruned pools are genuinely different pools, not one pool viewed two ways.

    Tuning: every method — DES, stacking, and the heterogeneous base learners — is tuned with the same Random Search budget (50 evaluations; 20 for heterogeneous base learners, which use halving). DES/OLA are tuned by leave-one-out scoring on the comparison set; stacking baselines use 3-fold CV.

    Metrics: MAE (reported here, lower is better), tuned and pruned independently.

    Pool architectures

    Each pool has a different source of diversity, which is what should decide whether DES has room to add value over the best member.

    Pool Members Diversity source
    Bagging-KNN 25 × KNN (k=5) Bootstrap resampling of rows
    Bagging-DT 25 × DecisionTree Bootstrap resampling of rows
    Subspace-KNN 25 × KNN (k=5) Random feature subspace (half the features per member)
    Subspace-DT 25 × DecisionTree Random feature subspace
    Heterogeneous Ridge, ElasticNet, KNN, DT, RF, XGBoost, MLP Different inductive biases, all tuned

    Methods compared

    • Oracle — per-point best model, an upper bound, not deployable.
    • SingleBest — best pool member chosen on the comparison set. The no-ensembling baseline.
    • SimpleAverage — uniform blend of all surviving members.
    • ValWeightedAverage — inverse validation-error weighting.
    • RidgeStacking / StackingRF / StackingGB — meta-learners over pool predictions.
    • OLA — overall local accuracy, selects the single best local model.
    • DEWS-U / DEWS-I / DEWS-V / DEWS-IV / DEWS-T — dynamic ensemble weighting schemes.

    % vs SingleBest = improvement over SingleBest. % HC = oracle headroom closed. Rank is 1 = best. Oracle is excluded from ranking commentary but shown for headroom.
